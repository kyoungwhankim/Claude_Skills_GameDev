# 분석 에이전트 공통 브리프 — {{TITLE}}

대상: {{TITLE}} (블루프린트·머티리얼·나이아가라 등 에셋 기반 언리얼 콘텐츠).
원본 .uasset 은 바이너리이므로 아래 텍스트 덤프만 분석한다. 에디터는 실행하지 않는다.

## 자료 위치 (모두 {{WS}} 아래)
- Dump/INDEX.md — 클래스 통계, 많이 참조되는 에셋, 로직 에셋 의존 요약, 폴더별 에셋 목록(파일 종류 표시)
- Dump/manifest.json — 에셋별 class, dependencies, referencers, tags
- Dump/vars/<에셋>.md — 블루프린트 변수표(카테고리·타입·툴팁·기본값)
- Dump/assets/{{ROOT_REL}}/... — 콘텐츠 루트 `{{ROOT}}` 기준 상대 경로. 에셋마다:
  - .props.txt : 패키지 내 모든 오브젝트의 프로퍼티(아키타입 대비 변경값). "=== 오브젝트경로 (클래스)" 헤더 뒤 "Prop = UE ExportText" 줄.
                 긴 배열은 "Prop[i] = ..." 원소별 줄. BP 변수 정의는 Blueprint 오브젝트의 NewVariables, 기본값은 Default__X_C 오브젝트.
                 "#ParentClass" 줄이 BP 부모 클래스.
  - .graph.txt : 읽기용 노드 그래프.
       BP/Niagara: "################ GRAPH <경로>" 블록, 노드 "[N7] 클래스 "제목" @(x,y)", 핀 "in/out 이름 (타입) = 기본값", "<- N3.핀" / "-> N9.핀" 연결.
       Material/MaterialFunction: "[E5] 클래스 "캡션"", "in 입력 <- E2.출력", ". 프로퍼티 = 값", 마지막에 [MATERIAL OUTPUTS].
  - .t3d : 에디터 복사 텍스트 원본(매우 큼, 세부 확인용으로만 grep).
  - .hlsl : 머티리얼 번역 HLSL(엔진 템플릿 포함, 실제 코드는 CalcPixelMaterialInputs 등 근처).
  - .niagara.hlsl : 나이아가라 시스템 컴파일 HLSL (CPU/VM, GPU; SimulationStageIndex 별 분기). 모듈 그래프에 여러 버전이 있으면 HLSL 이 실제 사용 버전의 기준.
- Docs/ — 수집한 공식 문서:
{{DOCS}}

큰 파일은 Grep 과 Read(offset/limit) 로 필요한 부분만 읽는다. 추측과 확인된 사실을 구분한다.

## 산출물
지정된 경로에 한국어 Markdown 섹션 파일을 Write 로 작성한다. 구성:
1. 개요 — 이 서브시스템이 무엇을 하는가 (2~5문장)
2. 구성 에셋 — 표 (에셋, 종류, 역할)
3. 동작 흐름 — 초기화 → 매 프레임 → 종료 순서, 다른 서브시스템과 주고받는 데이터(변수/파라미터/RT/채널 이름 명시)
4. 핵심 알고리즘/로직 — 수식·노드 체인 수준으로 구체적으로
5. 주요 파라미터 — 표 (이름, 기본값, 효과). 공식 문서 설명이 있으면 요약해 붙인다
6. 근거 — 주장마다 파일 경로와 그래프명/노드 ID(예: X.graph.txt GRAPH SetParams N42)
7. 불확실/추가 확인 필요 사항 (버그 의심은 근거 줄 번호와 함께)
mermaid 다이어그램이 도움이 되면 코드블록을 쓴다. 노드 라벨에 괄호·기호가 있으면 ["..."] 로 감싼다.

작업이 끝나면 최종 응답으로 (a) 작성한 파일 경로, (b) 다른 서브시스템과의 인터페이스 요약(변수·파라미터·RT·채널 이름 위주) 300단어 이내를 돌려준다.
