# /fab — Fab 검색 URL 생성기

사용자의 자연어 요청 → Fab 검색 필터 매칭 → **클릭 가능한 검색 URL**을 만든다.

## 절대 규칙 (Fab 약관 준수)

- **URL만 만든다.** Fab 사이트를 직접 열거나, fetch/WebFetch/브라우저로 결과를 가져오거나, `/i/*` 내부 API를 호출하지 않는다.
  Fab 서비스 약관 1.8조는 자동화된 수단으로 Fab 데이터를 수집·분석하는 것(스크래핑)을 금지한다.
- 결과 개수나 상품 목록을 추측해서 말하지 않는다. 결과 확인은 사용자가 링크를 열어서 한다.
- 사용자가 결과를 보고 상품 링크나 설명을 붙여 넣으면, 그 내용으로 비교·분석하는 것은 괜찮다.

## 입력 받기 (질문 창)

질문은 반드시 **AskUserQuestion 도구**로 창을 띄워서 한다. 채팅 텍스트로 묻지 않는다.

### 1단계: 자유 입력 (인자 없이 `/fab`만 입력했을 때)
- `/fab` 뒤에 설명이 붙어 있으면 이 단계를 건너뛰고 그 설명을 자유 입력으로 쓴다.
- 질문 1개짜리 창을 띄운다.
  - question: `어떤 에셋을 찾으세요? 자유롭게 설명하려면 아래 '그 외'(Other)에 입력해 주세요.`
  - header: `찾는 에셋`
  - options(4개): `환경·식생`, `캐릭터·크리처`, `VFX·이펙트`, `툴·플러그인`. 각 description에는 "그 외에 직접 쓰면 더 정확하다"는 안내를 짧게 넣는다.
  - '그 외'는 도구가 자동으로 붙여 주므로 options에 넣지 않는다.
- 사용자가 큰 분류만 골랐으면 그 분류를 출발점으로 2단계에서 구체적인 대상을 묻는 질문을 하나 넣는다.

### 2단계: 보충 질문 (최대 5개)
1단계 답을 분석해 **URL을 바꾸는 데 필요한데 빠진 정보만** 질문으로 만든다. 이미 답에 들어 있는 항목은 묻지 않는다. 필요한 게 없으면 바로 URL을 만든다.

질문 후보(필요한 것만 골라 우선순위 순으로):

| 후보 | header 예 | 선택지 예 (가능성 높은 순) |
|---|---|---|
| 구체적인 대상 | `대상` | 1단계 답에서 추론한 하위 대상 2~4개 |
| 스타일 | `스타일` | `사실적`, `스타일라이즈드`, `로우폴리`, `상관없음` |
| 대상의 형태 | `형태` | 요청에 맞게. 예: `스태틱 메시`, `애니메이션 포함`, `상관없음` |
| 품질 기준 | `품질` | `평점 4점 이상`, `AI 생성 제외`, `상관없음` (multiSelect 가능) |

**엔진 버전과 가격은 절대 묻지 않는다.** 사용자가 1단계 자유 입력에 직접 적었을 때만 필터에 반영하고, 적지 않았으면 해당 필터를 넣지 않는다.

질문 작성 규칙:
- 질문마다 options는 **가능성 높은 답 2~4개**다. 대부분 `상관없음`을 하나 포함한다.
- 직접 입력 선택지는 도구가 자동으로 붙이는 '그 외'(Other)를 쓴다. options에 따로 넣지 않는다.
- 가장 가능성 높은 선택지를 첫 번째에 두고 label 끝에 `(추천)`을 붙인다. 추천할 근거가 없으면 붙이지 않는다.
- header는 12자 이내.
- 여러 개를 고를 수 있는 질문(예: 품질 기준)만 `multiSelect: true`로 한다.
- AskUserQuestion은 한 창에 질문 4개까지다. **4개 이하면 한 창**에 모두 넣는다. 5번째가 꼭 필요할 때만 두 번째 창을 띄운다.
- 답이 `상관없음`이면 그 필터는 넣지 않는다. 답이 '그 외' 입력이면 그 내용을 해석해 필터나 `q`에 반영한다.

## 작업 순서

0. **입력 받기**: 위 "입력 받기" 절차로 자유 입력과 보충 답변을 모은다.
1. **요청 분석**: 아래 항목을 뽑는다. 요청에 없는 항목은 비워 둔다. 임의로 채우지 않는다.
   - 무엇을 찾는지(→ 검색어, 유형, 카테고리, 태그)
   - 엔진과 엔진 버전
   - 스타일, 기술 특징(Nanite, PCG 등), 파일 포맷
   - 가격, 무료 여부, 할인, 평점
   - AI 생성물 제외 여부, 플랫폼, 배포 방식(에셋 팩 / 코드 플러그인)
   - 정렬 기준
2. **필터 매칭**: [reference/filters.md](reference/filters.md)의 규칙과 값을 그대로 쓴다. 여기에 없는 slug는 지어내지 않는다.
   - 검증된 slug가 없는 개념은 영어 키워드 `q` 또는 `tags`로 표현한다.
3. **URL 조립**: 메인 링크와 다른 키워드 추천 링크를 만들어 아래 출력 형식대로 낸다.
4. **링크를 직접 열지 않는다.** 브라우저를 띄우는 명령(Start-Process 등)이나 앱 안의 브라우저 도구를 쓰지 않는다. 사용자가 표의 링크를 눌러 연다.
5. 보충 질문을 마친 뒤에는 더 묻지 않는다. 남은 모호함은 합리적으로 해석해서 바로 URL을 만든다.

## 매칭 원칙

- **규칙이 서로 다르면 `reference/filters.md`를 따른다.** 필터 규칙은 `/fabfilterupdate`가 그 문서에만 갱신한다.
- **검색어(`q`)는 영어로 짧게 쓴다.** 핵심 명사 1~3단어로, 예: `wild vegetation`, `modular dungeon`. 스타일이나 버전처럼 필터로 처리되는 단어는 `q`에 넣지 않는다.
- **엔진 버전**: "5.8"이면 `UE_5.8`. "5.6 이상"이면 `UE_5.6`, `UE_5.7`, `UE_5.8`을 모두 넣는다(OR).
  - 판매자들이 최신 버전 표기를 늦게 추가하는 경우가 많다. 그래서 단일 최신 버전만 요청하면 **넓은 링크를 하나 더** 준다. 넓은 링크는 바로 아래 하위 버전 1~2개를 포함하거나 버전 필터를 뺀다.
- **가격은 사용자 화면의 통화 기준**이다. 한국 계정이면 원화(₩)다. "$20 이하"처럼 달러로 말하면 원화로 대략 환산하고, 환산했다는 사실을 알린다.
- **평점·폴리곤·파일 크기 같은 범위 필터는 `min_`과 `max_`를 둘 다 넣는다.** 예: 4점 이상이면 `min_average_rating=4&max_average_rating=5`.
- **아트 에셋**(메시·머티리얼)에는 엔진 버전 필터를 걸 때 신중해야 한다. 아트 에셋은 버전 호환 문제가 적어서 필터를 걸면 쓸 만한 상품이 많이 빠진다. **코드 플러그인**은 버전 필터를 반드시 건다.
- **"AI 말고", "사람이 만든"** 같은 표현이 있으면 `is_ai_generated=0`을 넣는다.

## 출력 형식

**답변은 링크 표 하나로만 구성한다.** 열은 `구분 | 링크 | 설명` 세 개이고, 링크 칸에는 클릭 가능한 마크다운 링크를 넣는다.

```
| 구분 | 링크 | 설명 |
|---|---|---|
| 메인 | [underwater plants](<URL>) | 자연 및 식물 카테고리의 수중 식물 |
| 넓게 보기 | [underwater plants](<URL>) | 카테고리 제한 없이 3D 모델 전체 |
| 추천 키워드 | [seaweed](<URL>) | 해초·미역류 |
| 추천 키워드 | [kelp](<URL>) | 켈프 숲 |
```

- 첫 행은 **메인** 링크다. 필요할 때만 **넓게 보기** 링크를 둔다(버전 범위를 넓히거나 카테고리를 뺀 것).
- 이어서 **다른 키워드 추천** 2~4개를 링크로 준다. 판매자들이 같은 대상을 다르게 부르는 영어 키워드를 고르고, 메인과 같은 필터에 `q`만 바꾼 URL을 만든다.
- 링크 텍스트는 검색 키워드로 쓰고, 설명은 15자 안팎 한 줄로 쓴다.
- 표 앞뒤에 제목, 적용한 필터 표, 참고·주의 문단, 코드 블록, 맺음말을 넣지 않는다.
- URL 안에 `|` 문자가 들어가면 표가 깨지므로 `%7C`로 인코딩한다.

인코딩 규칙: URL 안의 공백은 `+`(q) 또는 `%20`(판매자 이름)으로 쓴다. 한글이나 특수문자는 퍼센트 인코딩한다. 링크가 깨지지 않도록 URL에 괄호나 공백을 남기지 않는다.
