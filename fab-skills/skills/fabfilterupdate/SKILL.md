# /fabfilterupdate — Fab 필터 규칙 갱신

`/fab`의 규칙 문서를 사용자가 직접 수집한 근거로 갱신한다.

- 규칙 문서: `~/.claude/skills/fab/reference/filters.md`
- 스킬 본문: `~/.claude/skills/fab/SKILL.md` (읽기만 한다. 고치지 않는다)
- 대조 스크립트: 이 스킬 폴더의 `scripts/compare_urls.py`

## 절대 규칙 (Fab 약관 준수)

- **Claude는 fab.com에 접속하지 않는다.** WebFetch, curl, 브라우저 도구로 페이지·JS 파일·`/i/*` API를 읽지 않는다. 테스트 URL을 대신 열어 보지도 않는다.
  Fab 서비스 약관 1.8조는 자동화 수단으로 서비스를 모니터링·분석하는 것을 금지한다.
- **근거는 사용자가 브라우저에서 직접 얻은 것만 쓴다.** 필터를 클릭한 뒤 복사한 주소창 URL, 스크린샷, "이 링크가 이상하다"는 보고가 근거가 된다.
- 근거 없이 값을 추측해서 문서에 넣지 않는다.

## 작업 순서

### 1. 현재 상태 파악
`filters.md`를 읽고 최종 확인일과 ⚠️ 항목 수를 한두 줄로 요약한다.

### 2. 사용자에게 무엇을 원하는지 확인
요청에 근거가 이미 있으면 바로 3단계로 간다. 없으면 아래 세 가지 중 고르게 한다.

- **A. 새 필터 찾기** — 아래 "수집 가이드"를 보여 주고 URL을 붙여 넣게 한다.
- **B. 기존 규칙 검증** — 아래 "검증 링크 만들기"로 링크 묶음을 만들어 준다. 사용자가 직접 열어 보고 결과를 알려 준다.
- **C. 문제 신고 처리** — 사용자가 이상하다고 한 `/fab` 링크를 받아 어느 파라미터가 의심되는지 짚고, B 방식으로 그 항목만 검증 링크를 만든다.

### 3. 근거 대조
- 붙여 넣은 텍스트에 URL이 있으면 스크립트로 대조한다. 텍스트는 임시 파일에 저장해서 넘긴다.
  ```
  python "<이 스킬 폴더>/scripts/compare_urls.py" "<filters.md 경로>" < 임시파일.txt
  ```
- 스크린샷이 오면 보이는 필터 이름, 옵션 이름, 주소창 URL을 읽어 같은 방식으로 비교한다.
- 검증 결과(B)는 항목마다 다음 중 하나로 분류한다.
  - 정상: ✅ 유지. ⚠️였다면 ✅로 올린다.
  - 효과 없음: ⚠️ 또는 ❌로 내린다.
  - 링크를 열면 파라미터가 사라짐: ⚠️로 두고 그 내용을 비고에 적는다.

### 4. 변경안 보고 → 승인
아래 형식으로 보여 주고, **승인받기 전에는 파일을 고치지 않는다.**

```
| 구분 | 파라미터 | 값 | 기존 | 변경 | 근거 |
|---|---|---|---|---|---|
| 추가 | styles | `noir` | 없음 | ✅ | 사용자 URL #3 |
| 상태 변경 | licenses | — | ⚠️ | ❌ | 검증 링크 결과 |
```
- 새 값이 slug인지 표시명인지 애매하면, URL에 찍힌 값을 그대로 쓴다.
- 표시명(한글 메뉴 이름)을 알면 함께 적는다.

### 5. 문서 수정
승인되면 다음을 고친다.
1. `filters.md`의 해당 표. 표 형식과 기호(✅ ⚠️ ❌)는 기존 문서를 따른다.
2. 맨 위 "최종 확인일"을 오늘 날짜로 바꾼다.
3. 맨 아래 "변경 이력" 표에 한 줄을 추가한다. 형식은 `| 날짜 | 무엇이 바뀌었나 | 근거 종류 |`.
4. URL 조합 규칙(OR/AND, min/max 쌍, 값 형식)이 바뀌었으면 `filters.md`의 "URL 구조" 절을 고친다. `fab/SKILL.md`는 고치지 않는다. 업데이트할 때 유지되는 파일은 `filters.md`뿐이라서, `SKILL.md`를 고치면 다음 업데이트에서 사라진다.
5. 바뀐 항목이 들어간 예시 URL이 문서에 있으면 함께 고친다.

마지막에 무엇을 바꿨는지 짧게 보고하고, 바뀐 필터를 쓰는 `/fab` 요청 예시를 하나 보여 준다.

## 수집 가이드 (A용, 사용자에게 그대로 안내)

브라우저에서 아래 순서로 클릭하고, 클릭할 때마다 **주소창 URL을 복사해서 메모장에 모은 뒤 한꺼번에 붙여 넣어 주세요.** 이미 아는 값은 건너뛰어도 됩니다.

1. `https://www.fab.com/search/channels/unreal-engine?q=tree`를 연다.
2. 왼쪽 **제품 유형**: 각 유형과 하위 카테고리를 하나씩 클릭한다. 지금 문서에는 3D, 툴 및 플러그인, 자연 및 식물만 확인돼 있다.
3. 위쪽 **스타일 / 기술적 특징 / 포맷**: 새로 보이는 옵션만 클릭한다.
4. **필터 더 보기**: 태그, 가격, 할인, 라이선스, 퍼블리셔, 퍼블리싱 날짜, 평가를 하나씩 설정한다.
5. **정렬** 메뉴: 새로 보이는 정렬 기준을 고른다.
6. 화면에 처음 보는 필터 그룹이 있으면 스크린샷도 함께 보낸다.

## 검증 링크 만들기 (B용)

- 검사할 항목을 고른다. 기본은 ⚠️ 전체이고, 사용자가 원하면 ✅ 전체도 검사한다.
- 항목마다 비교용 링크 두 개를 만든다.
  - 기준: `https://www.fab.com/search/channels/unreal-engine?q=tree`
  - 시험: 기준 + 해당 파라미터 하나
- 표로 준다: `| 항목 | 기준 링크 | 시험 링크 | 확인할 것 |`
  - "확인할 것"에는 다음 세 가지를 적는다.
    - 필터 칩이 붙는지
    - 왼쪽 "모든 제품" 숫자가 바뀌는지
    - 열자마자 주소창에서 파라미터가 사라지는지
- 사용자는 결과를 `항목: 정상 / 효과 없음 / 사라짐`처럼 짧게 답하면 된다고 안내한다.
